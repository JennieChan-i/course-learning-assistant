# 面试复习材料

## 我的项目介绍

我围绕 AI 产品经理课程的课后学习场景，设计了答疑、练习和薄弱点复习闭环。技术上使用本地混合检索与重排、两个有权限边界的 Agent、可选搜索 MCP 和可删除的学习记忆。我同时建立了消融实验和产品决策档案，避免仅通过架构图展示 AI 能力。

目前完成度与指标以验证记录为准。个人试用、人工标签、真实 API 效果和机构付费意愿仍需分别验证，不能互相替代。

## 常见追问

**为什么不直接用普通聊天工具？** 我的差异假设是：限定课程依据、可追溯引用、按课程出题、记录具体误解并安排复习。它是否足够形成持续使用与付费价值，需要用户验证。

**为什么需要 rerank？** 两路召回优先找全，重排重新评估问题与候选的相关性。它不能找回没有召回的资料。我保留质量、时延与成本对照，而不是默认它一定有效。

**为什么只有两个 Agent？** 教练和评估员的目标与上下文有实质区别。检索和数据库写入由确定性组件完成。两个角色使用同一模型可能共享偏差，因此我用单角色对照与人工评分检查实际收益。

**MCP 与 Tool Calling 有什么区别？** Tool Calling 是模型提出结构化调用请求的接口机制；MCP 是应用与工具服务之间的标准协议。应用仍负责权限与参数校验。项目通过 MCP 客户端连接搜索服务，而不是把普通函数改名为 MCP。

**Skills 是什么？** 我把教学任务写成有版本、输入输出和工具约束的可复用指令，运行时按需要加载。它与开发工具自己的 Skill 不是同一层，也不自动带来执行权限。

**Memory 怎样避免记错？** 用户明确提供的偏好与原始作答分开保存；评估结果作为学习证据，不能变成知识事实。失败评分不写入，重复提交幂等，删除后不再向上下文注入。

**Context Engineering 做了哪些具体工作？** 我分离任务、证据、偏好和历史，限制工具输出，优先删无关历史，为输出留预算。评估员不接收教练的主观评价，降低上下文污染。

**怎么判断答案正确？** 引用编号存在只是结构检查。还要把回答拆成事实主张，人工判断来源是否支持，并单独评估无答案处理。检索 Recall 高不能证明最终答案正确。

**为什么选择轻量模型？** 本机8GB显存、课程规模有限，优先满足任务质量与时延。小模型是基线，base 是受控对照；若增益不足，我保留小模型。公开小样本成绩不能直接迁移到私有课程。

**如何证明商业价值？** 我还不能证明。个人试用只能发现问题、建立初步信号。要验证机构价值，需要定义重复答疑基线、试用行为、人工介入情况及相应成本，同时验证机构是否愿意付费。

## 展示时的证据顺序

先演示一个具体学习任务，再展示来源与反馈；随后解释最关键的两项取舍；最后给出可复现评测与限制。只引用验证记录中的真实数字，不把未接入的 API、模拟评估或未审阅标签描述为线上实绩。

## 我怎样解释真实失败

- **“你做了双Agent，准确率提高了吗？”** 我还没有独立人工gold，不能这样声称。已完成40份候选的两流程对照，分别34份成功，31份配对中4份分数不同。双流程消耗更多Token与时间，这是实测成本；质量收益需要人工标签才能判断。修复后的失败复测单独保存。
- **“引用编号校验够了吗？”** 不够。基线暴露了拒绝回答仍复述伪造编号的问题，我同时修复提示词、澄清文本和流式边界。15条回归没有无效编号，仍不代表事实主张支持率已经合格。
- **“免费搜索300次为什么一下用完？”** 300是应用自设上限，免密服务限制和注册账户credits属于另外两层。我纠正了这个概念混淆，加入配置教程与明确降级，并用自己的免费密钥路径完成真实MCP验证。
- **“测试通过为什么还会出问题？”** 模拟断开测试没有暴露HTTP中间件遮住断开事件。真实TCP测试失败后，我改为纯ASGI中间件，把真实连接回归加入CI，证明停止任务不只停在界面。
- **“最主要的未解决问题是什么？”** 当前所选API模型响应慢，正式语义质量缺少独立人工gold。项目可以运行学习闭环，但还不能包装成所有质量与商业指标均已达标。
