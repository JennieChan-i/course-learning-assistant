# v1.0之后的迭代计划

这是我在冻结时的候选工作清单，不是排期承诺或已完成结果。我先修复阻断真实任务和可信度的问题，再验证学习价值和商业假设。没有真实使用频率、成本单价和收益估计时，不编造RICE分数或ROI。

## 优先级规则

- **P0**：一旦复现泄密、越权写入、错误成绩持久化、数据丢失或无法完成核心任务，立即停止相关功能的验收并修复。当前没有宣称存在新的未修P0事件；历史问题已修复并保留回归。
- **P1**：当前已有证据缺口或使用风险，优先处理质量标注、响应长尾和真实学习流程。
- **P2**：需要用户或机构证据后决定的扩展，不能仅为了技术展示插队。

## 下一版本的候选边界

| 候选版本 | 收录原则 | 进入验收所需证据 |
|---|---|---|
| v1.0.1 | 内测中复现的功能、状态、提示或边界缺陷修复 | 问题有复现步骤/运行ID，修复有相关回归；记录模型、提示词、Skill或数据是否变化 |
| v1.1 | 有人工反馈支持的质量与速度改进、闭环体验调整 | 与v1.0同条件对照、人工裁定、完整运行结果与负面结果；只对达到标准的能力标记通过 |
| 后续机构或平台版本 | 多租户、机构后台、付费、Dify迁移等 | 明确机构/维护需求和收益证据；先补权限、隔离、部署及成本方案 |

如果核心学习任务仍不可信，我先修复问题，不以扩展付费后台或增加Agent数量抵消缺陷。

## 指标如何计算

| 指标 | 分子 / 分母与记录要求 |
|---|---|
| 答疑解决率（人工体验信号） | 使用者明确认为解决了具体问题的轮次 / 实际被使用者评价的轮次；报告未评价数量，不把模型自评当用户评价 |
| 事实主张证据支持率 | 人工判断被本轮读取证据支持的事实主张 / 人工审核的全部事实主张；不确定、缺证据和不支持分别记录，默认不计作支持 |
| 无答案处理正确率 | 人工判断适当说明不足或澄清的无答案题 / 实际审核的无答案题；正常澄清不是请求错误 |
| 评分误差≤1比例 | 成功输出且与人工总分差≤1的样例 / 有人工gold且成功输出的样例；同时另报全部尝试、失败数与完成率，不能隐藏失败 |
| 练习完成率 | 成功提交并得到有效结果的轮次 / 生成成功且可作答的轮次；评测、演示与重复提交排除；待作答/主动放弃单独列出 |
| 复习执行率 | 实际完成有效复习作答的去重任务 / 观察期内到期且具备作答机会的去重任务；提前复习和观察期未到期分开 |
| Recall@10与NDCG@5 | 只在有独立相关性标签的可回答题计算；报告题数、父段级定义、数据范围及标注状态；未知题不混入检索分母 |
| 端到端P50/P95 | 从发送到首次有效内容、从发送到有效完成；按冷/热、任务和并发分组；失败/超时另报，不能把失败移除后宣称完整SLA |
| 调用成本 | 有实际单价才换算，分别记录教练、评估员、工具、失败和重试；缺失usage单列，不当成0 Token或免费 |

七天单人记录只能发现可用性和初步学习信号，不能推导市场规模、普遍学习效果或机构成本下降。定义改变时写明新旧口径，不在同一图表中直接比较。

## 每轮迭代的放行与撤销

1. 用[记录模板](review-template.md)登记问题、证据和期望结果，关联I编号。
2. 明确要改的变量和不应退化的能力；锁定题集、标注、配置与预算。
3. 保存原始基线，再实现最小改动；变更Skill、模型或数据都记录版本。
4. 完成相关回归与人工核对，比较失败、质量、时延和Token，保留全部尝试。
5. 达到预设条件则进入候选版本；质量下降、状态边界失败或收益不足则撤销/缩小。发布后新增CHANGELOG与版本档案，不移动旧标签。

Git回退不会自动迁移或回滚学习数据库。涉及数据结构或索引变化时先保存可恢复的本地备份，再写迁移/重建和验证步骤，不直接覆盖当前个人数据。
