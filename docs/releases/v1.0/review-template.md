# 我如何持续记录与复盘

这是空白模板，不是已经发生的访谈、试用或实验。个人作答、课程原文、运行日志与访谈原话存于本地 `runtime/` 的单独文件；公开档案只保留脱敏摘要、样例、结论范围和证据位置。不给未亲自核对的条目标记“人工通过”。

我为每条记录分配唯一ID，关联v1.0迭代清单的I编号、Git提交和运行ID。建议分别使用`ISSUE-日期-序号`、`EXP-日期-序号`、`TRIAL-日期-序号`和`DEC-日期-序号`，避免把同一天不同问题混成一条结论。

## 5. 阶段复盘与面试提炼

每轮内测或版本结束后，我写一页复盘：

1. **目标与边界**：本轮试图解决哪个用户任务，哪些只是技术验证？
2. **证据**：有哪些实际使用、原始报告、分母和人工裁定？哪些缺失？
3. **结果**：什么改善了，什么没有，代价是什么？是否有反例？
4. **归因**：哪些是数据、方案、实现、服务或评测口径问题？仍有什么替代解释？
5. **决策**：保留/撤销/暂缓什么，谁负责下一步，怎样判断结束？
6. **面试表述**：用“场景—取舍—行动—证据—局限”讲清一件事；只引用已记录结果，不把AI辅助实现说成已做用户访谈或独立人工评审。

我的v1.0复盘起点是：学习闭环已运行，真实边界问题已暴露并修复，轻量方案可用；但语义质量、响应长尾、真实学习价值与付费意愿仍有证据缺口。后续回答以实际补齐的记录为准。
