## 实际遇到的问题

1. GPU安装临时文件落在C盘造成空间不足：将TEMP/TMP和缓存移至项目目录后完成安装。
2. 本机8000端口被占用：默认改为8765，没有停止其他服务。
3. base embedding仓库的权重格式与其他模型不同：下载脚本识别safetensors或pytorch_model.bin，并检查权重实际存在。
4. 模拟协议测试故意返回未读取来源的题目时被拒绝：补全测试夹具中的真实工具读取后通过；生产中保留此验证。
5. 重排在锁定测试集排序质量下降：保留失败，待人工标签与新数据分析，不回头调测试集。

## 真实 API 接入记录（2026-10-25）

使用者配置的阿里云百炼 `kimi-k3` 已通过原生工具调用和流式输出检查。接入时发现固定温度0.2不被接受，因此改为默认省略温度，支持可选 `LLM_TEMPERATURE`。工具调用设为串行，课程内取得证据后直接进入生成，减少无用往返。

一轮私有课程答疑完成，来源编号校验通过，总耗时约54.78秒，包含首次加载本地模型。该结果没有达到首版响应时延目标，不能将其称为正式质量验收通过。三题生成在原45秒请求超时下失败，因此将请求超时改为可配置 `LLM_TIMEOUT_SECONDS`，默认120秒。延长超时只是避免过早中断，不等于提高速度。

测试使用独立数据库 `runtime/live-private/smoke-tests/`，没有把测试成绩写入正式学习档案。私有文本、密钥、完整响应和原始测试记录均留在本地。

初次出题的独立检查拒绝了证据不足的题目，修订又触发3500输出预算上限。随后收紧题目长度与主题，审核时优先提供实际引用片段，并为思考模型设置6000结构化输出预算与32768上下文上限。三题生成及独立审核成功，本轮77.18秒。这个样例验证流程可执行，不证明整体题目质量或学习效果。

随后完成同一轮的真实评分与教练反馈，耗时95.14秒，三份测试作答分别得到6/6、4/6、0/6。它们不是人工gold，不能据此声称评分准确率。测试问题合并为一个知识点复习记录，正式学习数据库不受影响。该速度明显不适合频繁即时练习；后续需要用相同质量标准比较更快的模型或服务，再由使用者决定是否替换。
