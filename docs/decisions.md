# 产品经理决策档案

我在开发过程中记录以下决策。日期：2026-10-24。状态分为已实现、待实测、待用户验证；“建议”不等于实验结论。

| 决策 | 依据与备选 | 我的选择与代价 | 验证与重新评估条件 |
|---|---|---|---|
| 用户边界 | 现有资料集中于 AI 产品经理，通用课程需求会扩大接入与评价难度 | 聚焦转岗学员，暂不做通用上传 | 用七天个人试用发现问题；后续访谈不能省略 |
| 商业定位 | 单人学习工具与机构配套均可行，但机构已有课程与答疑场景 | 将机构作为潜在付费方，先做学员端 | 尚无付费证据；机构访谈后再判断后台是否必要 |
| 学习闭环 | 仅聊天难以区分看懂与会用；面试训练会引入岗位评分体系 | 答疑→三题练习→薄弱点复习 | 检查反馈是否具体，复习是否真的改变作答 |
| 两个 Agent | 单角色更便宜；更多角色会增加协作成本 | 教练与评估员分工，普通答疑不调用评估员 | 评分消融需真实 API 和人工 gold；若无质量收益应收缩 |
| 本地模型 | 8GB显存、约15GB内存，课程规模877父片段 | small 中文 embedding＋base reranker；对照 base embedding | 开发集 NDCG 增益≥0.03且时延、显存达标才切换；不能按榜单直接决策 |
| 索引 | 外部向量服务增加部署成本；纯数组需要自建元数据与过滤逻辑 | Qdrant 本地模式，单进程独占 | 数据量与并发扩大时迁移服务模式 |
| 父子切分 | 原片段平均约622字，短模型输入可能截断 | 保留引用父段，检索子段；双 tokenizer 检查 | 检查切分位置与引用还原；对重叠做后续实验 |
| 清洗可信度 | 已清洗文件仍含口语与课堂信息 | 规则标记疑点，不自动改写知识事实 | 人工审核质量报告；语义错误与检索错误分别归因 |
| MCP 选型 | 用户希望外部搜索且尽量免费 | Tavily 基础搜索，无付费套餐，默认关闭 | 免费条款与可达性可能改变；上线前再次核查，失败明确降级 |
| Skills | 将所有教学方式塞进固定系统提示难以版本管理 | 三个小 Skill，按任务加载 | 保留版本、实验与工具权限；不引入任意脚本执行 |
| Memory | 全对话作为长期记忆会混淆事实与推断 | 明确偏好＋有效作答，删除后不再注入 | 测试重启、删除、幂等与失败不写入 |
| 公开数据 | 完整课程公开传播权限未确认 | Git忽略课程与衍生数据，公开独立自编样例 | 发布前扫描暂存区、截图与报告；用量与标签不跨数据集混报 |
| 界面 | 用户偏好 Codex，学习主要在桌面发生 | 侧栏、中央工作区、来源详情；支持窄屏与明暗主题 | 浏览器检查完整流程，不以构建成功替代交互验证 |
| 可复现性 | Windows 默认临时目录在 C 盘，首次 GPU 安装遇到空间不足 | 把 pip 临时目录与缓存设置到项目 D 盘 | 实际 GPU 运算和两类模型推理通过后才标记本地可用 |
| 端口 | 本机 8000 已被其他服务占用 | 默认8765，可配置，不停止其他进程 | 启动脚本输出明确地址，Origin 校验跟随端口 |

## 每次迭代的记录格式

问题与触发证据 → 候选方案 → 我选择的方案 → 预期收益与成本 → 验证方法 → 实际结果 → 风险与再次评估条件。

如果结果不支持我的预期，我保留失败结果，不把它重写为“设计本来就正确”。

## 接入后的决策补充（2026-10-25）

实际接入使用者选择的 kimi-k3 后，发现固定温度不兼容、并行检索冗余、证据摘录过短、45秒超时和3500输出预算不足。我的修复是让温度可选、工具串行、拿到证据即进入回答、独立评估优先读取实际引用片段，并显式配置超时与结构化输出预算。参数也进入运行记录。

三题生成审核与评分反馈已经跑通，但77秒和95秒的实测耗时不满足快速学习交互的期待。延长超时保证可完成，不等于满足性能要求。我保留使用者的模型选择；下一步应在同一组经过人工审阅的题目上对照速度、评分质量和成本，不以更换模型名称代替评测。

## 实测后继续迭代（2026-10-25）

| 问题与证据 | 备选与选择理由 | 成本、风险与验证 | 实测与再次评估条件 |
|---|---|---|---|
| 普通问答额外的意图模型往返增加等待 | 保留分类调用或合并进检索工具；我选择合并，仍保留结构化意图、追问改写与澄清 | 工具 Schema 略增；回归检查澄清不检索、最近对话传入 | 60条问答基线和15条修复回归已执行；时延目标仍未全面通过 |
| 80份候选作答的评分中4个批次失败 | 无限制重试会隐藏故障和增加费用；我选择格式最多修复一次，超时由显式复测触发 | 两模式各34/40成功；失败报告永久保留，不与新版本拼接成完整成功实验 | 4个失败批次均在新版本复测成功；没有人工 gold，不声明双Agent准确率更高 |
| 拒绝伪造来源时仍复述假引用 | 只依赖提示词或增加流式引用校验；我选择两者结合 | 括号跨数据包时短暂缓存；错误轮不写入历史 | 修复后15条开发回归无请求错误和无效引用；完整人工支持率仍待标注 |
| 免密服务额度受限造成“免费300次”的误解 | 免密作为默认或使用个人免费密钥；我选择默认需密钥，免密仅可选 | 项目请求上限与账户credits分别说明；默认不联网、不升级付费 | 使用者免费密钥已完成真实MCP发现与搜索；额度或工具Schema变化时重验 |
| 六条课程候选挤掉外部资料 | 全部拼入上下文会扩大预算；我选择总上限六条，外部最多三条 | 课程证据略少，需评测资料相关性；不能把第三方文章包装成官方核查 | 原生工具→真实MCP→带外部引用回答已跑通；补充站点限定并验证官方资料 |
| 真实连接取消后后端仍继续工作 | 模拟取消测试未覆盖中间件影响；我改用纯ASGI边界并加入真实TCP测试 | 增加一个本机连接回归；取消不能撤销服务商已处理的请求 | 真实断开测试通过，结果不写入且任务锁释放；流式与评分流程变更后重验 |
| 人工标注停留在手工编辑JSONL | 自动AI标注不能当人工gold；我增加独立审阅页面和本地版本化标注 | 增加少量开发者界面；只有真实审阅者确认才计入人工指标 | 候选原文件哈希不变、无来源和无人工分数被拒绝、重启保留已验证；仍需使用者逐题审阅 |

推理力度对照后，我选择只降低教练的推理力度，保留评估员默认设置。证据是相同模型上三题首次内容由约15–33秒降为约7–9秒，成本是尚未证明语义质量不变；因此保留原始回答、另跑开发回归，并把正式质量和P95继续标为待验证。若人工评分下降、来源支持不足或更多问题速度没有改善，应撤销覆盖或比较其他服务。

我还将搜索计数从各学习数据库迁到项目共享预算，避免切换课程或清空学习历史突破月度300次上限。独立测试验证两个学习库共享限额且清空记录不重置。

## Dify备选架构梳理（2026-10-25，仅设计）

使用者希望理解整体产品架构及Dify搭建步骤。我对照现有代码和Dify1.18.0官方资料，保留代码版作为当前实现，提供“Dify负责可视化编排，本地域服务负责检索、长期记忆、权限、预算和事务”的迁移方案。

备选包括全部依赖Dify内置知识库与标准界面，以及保留当前代码。推荐混合方案的理由是避免丢失父子片段追溯、实际tokenizer检查、精确课程范围、引用拦截和学习状态幂等。代价是新增受控适配API，以及Dify自身数据库、Redis、插件和容器资源；不承诺更快或更轻。

验证方法是在同一模型、数据与评测题上比较两版质量、时延、Token、修改流程成本与资源占用。当前只完成架构文档、39步教程及参考契约和示例检查，没有部署Dify或验证迁移收益。新版Agent和原生Skills另列为Beta可选路线，不与经典节点教程混用。若迁移无明确维护或用户价值收益，继续代码版。

## v1.0基线冻结（2026-10-25）

使用者决定将当前产品作为v1.0，便于后续复盘与迭代。我将其标为v1.0.0个人内测基线，统一前后端版本元数据，并在[版本档案](releases/v1.0/README.md)记录范围、重要节点、决策、验证、风险、迭代优先级和记录模板。代码与公开报告使用可核对指纹，Git标签定位交付，不复制密钥、原课程、模型权重或个人记录。

版本命名与质量成熟度分开：已有实测不能补足人工gold、七天试用或商业验证；Dify设计也不作为已实现能力。后续按证据决定v1.0.1修复和v1.1候选改进，不移动v1.0标签，也不把新结果回写成旧基线的成功。冻结后本次自动测试与构建再次执行，真实API评测沿用注明配置的历史报告，没有为归档额外消耗模型或搜索额度。

## v1.1：从反馈到验证（2026-10-26）

我基于v1.0增加badcase闭环。核心缺口是问题缺少用户入口、历史日志缺少复现上下文、修复缺少有标准的复验。备选包括只保存反馈文本、自动用模型给标签、另建工单平台。我选择在现有应用增加两张表，复用traces、两Agent和课程检索，明确待核查→人工确认→处理→验证→关闭的边界。

固定历史资料池用于生成/评分复测，当前知识库用于检索修复验证；两者用临时学习库，避免测试作答改变真实复习计划。归因、期望行为和修复版本的指纹与最新人工复验绑定；数据/检索/排序案例不能通过固定资料池关闭。导出独立回归集，不把已知问题混入锁定测试集。

主要代价是本机快照存储、人工核查工作和真实复测的LLM Token。关联偏好变化后清除现场；下载副本需自行管理。发现多条反馈清空说明后会触发唯一约束，我保留每条匿名反馈标识解决冲突；增加断开连接、重启中断与未提交答案保护回归。64项自动测试通过，自编课程真实API答疑复测完成，人工语义质量仍待审阅。

再次评估条件是实际反馈量显著上升、重复归因人工成本明显，或质量标准需要多人复核；当前不增加归因Agent、语义聚类和团队运营平台。完整决策表、关键节点与限制见[v1.1档案](releases/v1.1/README.md)及[操作说明](badcase.md)。本轮仅修改本机代码版，不据此宣称Dify工作流已接入同样机制。
