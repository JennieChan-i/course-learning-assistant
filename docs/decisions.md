# 产品经理决策档案

我在开发过程中记录以下决策。日期：2026-10-24。状态分为已实现、待实测、待用户验证；“建议”不等于实验结论。

| 决策 | 依据与备选 | 我的选择与代价 | 验证与重新评估条件 |
|---|---|---|---|
| 用户边界 | 现有资料集中于 AI 产品经理，通用课程需求会扩大接入与评价难度 | 聚焦转岗学员，暂不做通用上传 | 用七天个人试用发现问题；后续访谈不能省略 |
| 商业定位 | 单人学习工具与机构配套均可行，但机构已有课程与答疑场景 | 将机构作为潜在付费方，先做学员端 | 尚无付费证据；机构访谈后再判断后台是否必要 |
| 学习闭环 | 仅聊天难以区分看懂与会用；面试训练会引入岗位评分体系 | 答疑→三题练习→薄弱点复习 | 检查反馈是否具体，复习是否真的改变作答 |
| 两个 Agent | 单角色更便宜；更多角色会增加协作成本 | 教练与评估员分工，普通答疑不调用评估员 | 评分消融需真实 API 和人工 gold；若无质量收益应收缩 |
| 本地模型 | 8GB显存、约15GB内存，课程规模877父片段 | small 中文 embedding＋base reranker；对照 base embedding | 开发集 NDCG 增益≥0.03且时延、显存达标才切换；不能按榜单直接决策 |
| 索引 | 外部向量服务增加部署成本；纯数组需要自建元数据与过滤逻辑 | Qdrant 本地模式，单进程独占 | 数据量与并发扩大时迁移服务模式 |
| 父子切分 | 原片段平均约622字，短模型输入可能截断 | 保留引用父段，检索子段；双 tokenizer 检查 | 检查切分位置与引用还原；对重叠做后续实验 |
| 清洗可信度 | 已清洗文件仍含口语与课堂信息 | 规则标记疑点，不自动改写知识事实 | 人工审核质量报告；语义错误与检索错误分别归因 |
| MCP 选型 | 用户希望外部搜索且尽量免费 | Tavily 基础搜索，无付费套餐，默认关闭 | 免费条款与可达性可能改变；上线前再次核查，失败明确降级 |
| Skills | 将所有教学方式塞进固定系统提示难以版本管理 | 三个小 Skill，按任务加载 | 保留版本、实验与工具权限；不引入任意脚本执行 |
| Memory | 全对话作为长期记忆会混淆事实与推断 | 明确偏好＋有效作答，删除后不再注入 | 测试重启、删除、幂等与失败不写入 |
| 公开数据 | 完整课程公开传播权限未确认 | Git忽略课程与衍生数据，公开独立自编样例 | 发布前扫描暂存区、截图与报告；用量与标签不跨数据集混报 |
| 界面 | 用户偏好 Codex，学习主要在桌面发生 | 侧栏、中央工作区、来源详情；支持窄屏与明暗主题 | 浏览器检查完整流程，不以构建成功替代交互验证 |
| 可复现性 | Windows 默认临时目录在 C 盘，首次 GPU 安装遇到空间不足 | 把 pip 临时目录与缓存设置到项目 D 盘 | 实际 GPU 运算和两类模型推理通过后才标记本地可用 |
| 端口 | 本机 8000 已被其他服务占用 | 默认8765，可配置，不停止其他进程 | 启动脚本输出明确地址，Origin 校验跟随端口 |

## 每次迭代的记录格式

问题与触发证据 → 候选方案 → 我选择的方案 → 预期收益与成本 → 验证方法 → 实际结果 → 风险与再次评估条件。

如果结果不支持我的预期，我保留失败结果，不把它重写为“设计本来就正确”。
