# 我如何在 Dify 页面上亲手搭建课程智能学习助手

这是一份从空白 Chatflow 开始的实操教程。我希望学习者既能照着操作完成产品，也能解释每一步产品决策。主线使用 Dify Cloud 的画布、知识库、模型、工作流工具和 MCP，不要求先写后端或安装 Docker。

**适用页面：2026-10-25 实际登录的 Dify Cloud 中文界面。** 我核对了主页、创建空白应用弹窗、现有 Chatflow 的 LLM/知识检索面板、会话变量、添加节点菜单、集成与 MCP 弹窗。Agent 策略、知识库创建的后续操作同时参考官方文档；没有在账号中创建、发布教程应用，也没有消耗模型额度来宣称验收成功。Cloud 可能滚动更新，本文不把开源发行版本号当作你账号的版本号。

每章都有“点哪里、填什么、看到什么、为什么、怎么测”。先完成一章的检查，再进入下一章。教程中的 `Q01`、`P01` 等是我建议你手动填写的节点名称，方便排错；它们不是 Dify 自动生成的 ID。

**变量记法：** `「节点名 / 输出字段」` 表示在输入框点变量选择器或输入 `/`，再点选那个字段。不要把这几个汉字直接粘贴进去。提示词中的 `〈插入…〉` 也要替换成真正的变量标签。代码块中的 Python 则整段复制到“代码执行”节点。

## 我准备复现到什么程度

| 本地产品 | 本教程中的实现 | 对齐情况与限制 |
|---|---|---|
| 课程答疑、来源、无答案处理 | 知识检索→带证据的教练→直接回复 | 业务行为复现；Dify 引用展示依赖上下文绑定及功能开关，需实际检查 |
| BM25+向量+RRF+rerank | 高质量知识库的混合检索与 rerank | 保留混合检索思想；不能把 Dify 内部排序称为原项目的 RRF 配置 |
| 本地 BGE small/base、5060 Ti | 主线先用账号已可用的云端 embedding/rerank | 这是部署差异。Cloud 无法直接读取电脑模型目录或访问电脑的 127.0.0.1 |
| 两个 Agent 职责 | 教练出题/辅导，评估员独立审核/评分 | 先搭可控双角色流程，再用 Agent 节点实验工具调用；多个 LLM 方块本身不证明自主协作 |
| 原生 Tool Calling | 检索 Workflow 发布为工具→Function Calling Agent | 在运行详情里检查真实工具名、参数和结果 |
| 版本化应用 Skills | 三份指令按路由加载到不同节点 | 保留指令版本与按需加载；经典 Chatflow 不因此获得 New Agent 的原生 Skills 运行时 |
| SQLite 学习档案 | 一个会话变量保存偏好、待作答题、近期成绩、复习队列 | 同一聊天内复现；跨新会话、跨设备的用户档案与事务写入需要持久化服务 |
| 1/3/7 天复习 | 代码根据有效评分排期 | 透明规则复现；到期后用户输入 `/复习`，不会自动推送 |
| Tavily MCP | 集成→工具→MCP→基础搜索节点 | 真实 MCP；默认只有明确输入 `/联网` 才调用 |
| 每月全局 300 次预算 | 主线仅做每会话计数与单轮一次调用 | 全局并发原子配额需要共享存储，提示词和会话变量不能替代 |
| React 桌面工作台 | Dify 自带 Web App | 学习流程复现；三栏工作台、历史管理页不由画布自动生成 |
| API/GPU 性能、人工金标评测 | 本教程提供测试卡和记录表 | 必须重新实测，不能沿用本地成绩 |

完整保留本地 GPU、数据库、引用校验和全局配额时，才需要后续工程集成。原有 [工程迁移方案](../dify-build-guide.md) 放在进阶位置；它不是本教程的前置条件。

## 我为什么这样安排

我先验证“课程回答是否有依据”，再增加状态和工具，避免一开始无法定位错误。出题和评分分开，是为了检验独立评估能否减少出题者替自己辩护；是否有效由消融实验决定。云端原型有帮助，但部署取舍、数据边界和验收证据仍是产品经理的工作。

主线使用自编的 [16 个课程片段](knowledge/)，对应仓库公开样例；完整私人课程不随教程发布。不要上传模型权重、`.env`、学习记录或课程原始文件来“配置 Dify”。Dify 云端凭据要在它自己的集成页面配置，本地 `.env` 不会被自动读取。

本教程借鉴你提供的两份文稿的教学方式：逐步搭节点、查看中间变量、试错与复盘。产品内容、提示词和代码是为这个项目新写的，不把医院导诊、简历优化等功能加入首版。

本次核查范围、实际决策与未执行项目见 [实现选择与验证状态](实现选择与验证状态.md)。
