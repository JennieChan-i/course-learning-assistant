## 失败案例与产品决策

### DIF-007：为什么关闭 rerank

- **问题：**课程可检索是学习闭环的前置条件；默认 `qwen3-rerank` 尚未证明本账号可稳定调用。
- **证据：**指定 embedding 已完成全库索引；无模型 rerank 的混合检索已返回相关课程片段。此前其他通义模型调用遇到 `AllocationQuota.FreeTierOnly`，不能把模型列表中可见等同于可调用。
- **备选：**等待 rerank 额度或新增付费模型；使用混合权重排序；退回纯关键词。
- **选择：**保持混合检索，语义 0.7、关键词 0.3，Top K=6。用户明确允许没有 rerank 时不用。
- **成本与风险：**候选片段排序质量可能较弱；单题成功不足以判断整体质量。
- **验证：**先测试完整课程的问答和练习，再用锁定题集比较无 rerank 与可用 rerank 的 NDCG@5、事实支持率和延迟。
- **再次评估条件：**获得稳定且成本可接受的 rerank 服务，并看到质量提升足以抵消延迟和费用。

### DIF-008：为什么所有 Kimi 节点不传 temperature

- **问题：**从通用 LLM 模板复制出的参数可能被具体模型拒绝。
- **证据：**Dify 预览在 I01 意图识别返回 HTTP 400，明确指出 `Parameter 'temperature'=0.7 is not supported for kimi-k3 model`。
- **选择：**在生成器中统一去掉所有 Kimi-k3 的 temperature，而非只修 I01。避免下一段 LLM 或 Agent 再因相同参数中断。
- **验证：**同一问题重新预览，并分别跑答疑、练习、评分和联网分支。
- **再次评估条件：**更换 LLM 服务商/型号后重读模型契约，按该模型实际支持的参数设置。

### DIF-009：Cloud 模型与本地模型的界限

用户指定的 embedding 已在 Dify Cloud 工作空间完成索引。这满足“Dify 版用指定模型”的要求，但它不使用本机 5060 Ti，也不保证与本地 BGE 索引有相同结果。Dify 版用于快速验证体验和产品逻辑；本地版仍承担本机模型与长期学习档案的工程能力展示。面试时我会明确说明两套实现的差异，不把同一产品名下的能力混为一谈。
