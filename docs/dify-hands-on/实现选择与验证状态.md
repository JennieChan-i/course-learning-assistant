## DIF-001：以原生画布作为教学主线

- 问题：工程迁移需要后端适配，不能满足“自己点页面从零搭”的学习目标。
- 证据：用户明确要求按照两份文稿的点击、填写、解释方式学习，当前账号已可用 Chatflow。
- 备选：Dify+本地领域服务；Dify原生Cloud；重新部署自托管。
- 选择：原生Cloud先复现学习闭环，工程集成作为进阶。
- 成本/风险：不能完全复现本地GPU、React工作台、持久事务和全局预算。
- 验证：按教程搭完核心流程，再逐项核对差异表；未搭建，不报告通过率。
- 重新评估：需要私人课程本地保留、跨会话长期档案或精确全局配额时。

另一个候选是 New Agent：官方说明它带沙箱、Skill、工具和文件，并能嵌入工作流；当前仍标 Beta。它适合开放式任务，本教程的核心是可检查的证据与状态流程，暂时不需要命令执行和文件运行环境。我因此选择经典画布作为主线；这是本项目范围下的取舍，不是说 New Agent 不能实现。将来要教学原生 Skill 发现/加载时可另开副本对照。[New Agent 官方说明](https://docs.dify.ai/zh/cloud/use-dify/build/new-agent/overview)

## DIF-002：先可控双角色，再验证自主工具调用

- 问题：直接堆多个Agent，会同时引入路径、格式和评分不稳定。
- 备选：单教练全做；固定教练/评估员；两个Agent自主循环。
- 选择：两角色固定交接，独立评估上下文；在副本用Function Calling实验自主核查。
- 取舍：保留基线便于归因；不能把固定LLM流程本身包装成已验证的自主Multi-Agent。
- 验证：相同题目和作答的人工评分一致性、格式失败、Token和延迟；真实工具轨迹。
- 实测：尚未在Dify执行，只有确定性代码检查通过。
- 重新评估：工具核查显著改善评分或复杂问题检索，并能接受新增等待时。

## DIF-003：正式提交用明确入口

- 问题：学习者询问题意与提交答案容易被语义分类混淆。
- 选择：用/作答加三题格式，路由校验pending和答案完整性；普通问题不记成绩。
- 备选：完全自然语言猜测；增加专用前端按钮与表单。
- 成本：命令式界面有学习负担；后续可换按钮，保留同一状态规则。
- 验证：格式缺失、重复题号、重复交卷、评分注入、退出练习测试。
- 实测：离线规则检查通过；真实Dify画布仍待验证。

## DIF-004：显式近期上下文与可纠正偏好

- 问题：删除偏好后，自动聊天历史可能把它再次带回。
- 选择：所有相关节点关闭自动Memory，只用受控context；删除偏好同时清空近期对话。
- 成本：按条数和字数限制不等于精确token预算；同一聊天状态不等于长期用户档案。
- 验证：比较删除前后实际模型输入，新聊天重置范围；不宣称删除平台日志。
- 实测：离线偏好与上下文检查通过；模型输入检查待执行。

## DIF-005：外查默认关闭，只开放一种基础MCP工具

- 问题：时效问题需要外查，但课程正文、档案和费用不应随意外传。
- 选择：明确/联网后执行一次MCP基础搜索，不自动抓取、不进入课程评分。
- 成本：比按需自主联网保守；每会话10次计数不是全局每月300次。
- 验证：未授权0调用、失败无重试、参数固定、次数上限和未核实提示。
- 实测：配置界面已核对；真实服务鉴权、调用与额度尚未在新应用执行。
- 重新评估：需要服务端全局配额、自动时效判断或机构使用时。

## DIF-006：保留证据单元，但不伪称复现检索算法

- 选择：演示材料保留S01–S16来源编号，主线使用Dify高质量混合检索与可用rerank。
- 差异：Dify分段参数、排序实现与本地双tokenizer、父子片段、RRF不是同一个配置。
- 验证：分段预览、预期来源与真实排名、配置消融；完整课程独立做数据审计。
- 实测：16个公开样例文件已生成，长度均低于教程800字符上限；云端embedding效果待测。

用户实操反馈Sandbox每次只允许一个文件后，我改为单文件CSV主线，保留16份txt作查看样例。单列content含来源与正文，排除suitable_questions；正式课程导出保留877条，输出在本地runtime，不公开。代价是合并文档不能直接按文档级元数据区分课程；主线先全部课程，单课过滤再按课程分文档配置。生成与CSV回读检查已完成，Dify云端分段与检索仍需预览验证。
